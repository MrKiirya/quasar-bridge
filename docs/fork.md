# Доработки форка

Разделы руководства для настроек, которых нет в upstream. Остальное — в [wiki upstream](https://github.com/skrashevich/quasar-bridge/wiki).

## Разговор с нейросетью без повторного обращения

Обычно следующий вопрос после ответа нейросети выбирает маршрут по своему тексту:
«расскажи про Марс» без «Клод» уйдёт Алисе. С `"llm_conversation": true` такой вопрос
остаётся у нейросети, пока колонка сама слушает дальше после её ответа. Признак —
отчёт колонки о запросе (`RequestStat`): ответ доигран до конца и не перебит, а новый
голосовой запрос пришёл не позже секунды после этого отчёта. Колонка открывает его
сразу по окончании ответа; «Алиса» посреди ответа перебивает его, а после — приходит
через секунды. Поэтому «Алиса, …» возвращает к обычному выбору маршрута, как и
запрос, распознанный с «Алиса» в начале или начатый своим словом активации
station-wakeword с меткой (его маршрут выбирают правила с `wake_words`).

Разговор заканчивается, когда колонка перестаёт слушать (тишина), после «Алиса»,
после ответа не нейросети, ответа с ошибкой и после текстового запроса. Явные
правила `routing` действуют и в разговоре: «стоп» уходит по своему правилу.
Классификатор в разговоре не спрашивается, поэтому команда умного дома без
подходящего правила (например, `home_devices`) тоже уйдёт нейросети.
Продолжение пишется в лог как `native_conversation`, решение — с источником
`conversation`. Работает только вместе с `listen_after_reply`; нужен перезапуск.

## Подсветка маршрута на кольце

На колонках с RGB-кольцом мост может перекрашивать собственную анимацию Алисы
в цвет маршрута: ответ нейросети, умного дома или музыки с сайта идёт тем же
переливом «думает» и «говорит», но другим цветом. По умолчанию подсветка
выключена. Добавьте блок в основной конфиг и **перезапустите** Go-сервис:

```json
{
  "route_indicator": {
    "enabled": true,
    "colors": {"llm": "#ff5000", "home": "#18bcf2", "music": "#00c8b4"}
  }
}
```

Прошивка рисует анимацию, открывая файлы яркости кольца в `/sys/class/leds`
на каждом кадре. Когда маршрут запроса получает цвет, мост накладывает поверх этих
файлов заглушки в `/tmp/quasar-bridge-ring` (`mount --bind`): прошивка продолжает
рисовать в них, а мост переносит каждый кадр на кольцо в цвете маршрута. От прошивки
берутся моменты и места свечения (включение, бегущий провал, затухание), а поверх мост
накладывает волну яркости 45–100 % с периодом 1,6 с: Pro-анимации меняют в основном
оттенок, и без волны перекрашенное кольцо выглядело бы ровным цветом. Подсветка снимается, когда прошивка гасит
кольцо на `idle_ms` (100–10000, по умолчанию 600 мс), начинается новый запрос,
приходит маршрут без цвета или проходит `max_ms` (1000–600000, по умолчанию 60000 мс).
После снятия на кольцо возвращается последний кадр прошивки.

На Станции Лайт 2 (а по описанию — и на Миди и Мини 3 Про) прошивка рисует кольцо
во framebuffer (`/sys/class/graphics/fb*/name` с `ring`), а светодиоды в
`/sys/class/leds` повторяют его через LED-триггер ядра (`led_ring_fb`, `ledfb-ring`).
Мост узнаёт это по триггеру кольца при запуске и включает режим framebuffer: кадры
прошивки читаются из `/dev/fbN` (яркость пикселя — его самый яркий байт, пиксель N —
N-я зона по порядку; при другом числе пикселей — яркость всего кадра), на время
подсветки триггеры отключаются, а при снятии подключаются обратно. Ядро приглушает
кадр, например по датчику освещённости, поэтому перед подсветкой мост сравнивает
кадр со светодиодами и сохраняет то же приглушение. Колонки, у которых кольцо есть
только во framebuffer (Мини 3, Станция 2), не поддерживаются: прошивка перерисовывает
кадр сама.

Цвета из `colors` заменяют значения по умолчанию только для указанных маршрутов;
пустая строка оставляет маршруту цвета прошивки. Ответы Яндекса (`yandex`) по
умолчанию не перекрашиваются. Формат цвета — `#rrggbb`. Маршрут `llm` становится
известен, когда ответ модели готов, поэтому перекрашивается в основном «говорит»;
при переходе к нейросети после отказа Алисы — и ожидание ответа. Новый запрос
сразу возвращает кольцо прошивке, пока его маршрут не определён.

Подсветка работает только в режиме `hybrid`, нужен root. Если мост убит во время
подсветки (`SIGKILL`, нехватка памяти), заглушки остаются и кольцо замирает, а в режиме
framebuffer остаётся тёмным, до следующего запуска моста или перезагрузки колонки:
при старте мост снимает оставшиеся заглушки и подключает триггеры из
`/tmp/quasar-bridge-ring/triggers` в любом режиме, даже с выключенной подсветкой. Кольцо ищется
по именам `<модель>:{red,green,blue}:ring<N>`; если его нет, подсветка отключается
с предупреждением `route_indicator_unavailable`. Режим (`sysfs` или `framebuffer`)
пишется в журнал при запуске в событии `route_indicator`. `/healthz` показывает
`route_indicator_enabled`.

| Колонка | Режим | Состояние |
| --- | --- | --- |
| Станция Мини 2 | `sysfs`, 6 зон | проверено на устройстве до появления режима `framebuffer`; путь `sysfs` с тех пор не менялся |
| Станция Лайт 2 | `framebuffer`, 3 зоны, триггер `led_ring_fb` | проверено на устройстве |
| Станция Миди, Мини 3 Про | `framebuffer`, триггер `ledfb-ring` (по описанию прошивки) | не проверено |
| Станция Лайт, Станция Макс с Zigbee | кольцо в `/sys/class/leds`, режим определяется при запуске | не проверено |
| Станция Мини 3 | кольцо только во framebuffer | не поддерживается, предупреждение |
| Станция 2, Мини, Стрит, Хаб, JBL Link | кольца в `/sys/class/leds` нет | подсветка не включается, предупреждение |

На колонках без поддержки мост не трогает светодиоды и их триггеры.

## Справочник конфигурации

| Ключ | Описание |
| --- | --- |
| `llm_conversation` | Оставлять у нейросети вопрос, который колонка слушает сразу после её ответа; по умолчанию `false`, требует `listen_after_reply`, требуется перезапуск |
| `route_indicator` | Перекраска анимации кольца по маршруту: `enabled`, `colors`, `idle_ms`, `max_ms`; только `hybrid`, по умолчанию выключена; требуется перезапуск |
